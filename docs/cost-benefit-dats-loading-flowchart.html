QuantiFarm Switzerland - Data Flow Architecture

📊 Overview

This flowchart visualizes the complete data flow for Cost-Benefit Digital Agriculture Technologies (DATs) in the QuantiFarm Switzerland platform. The process transforms Excel-based DAT definitions into a semantic knowledge graph and delivers them through APIs to the user-facing Cost & Benefit Calculator interface.

Key Components: Excel Sources → Python ETL Loader → Apache Jena Fuseki Triple Store → FastAPI Services → PHP Backend → JavaScript Frontend → HTML UI

📊 Source Data

Excel files containing DAT definitions with cost information, separated by agricultural sector (Arable vs Livestock).

2️⃣ DATs Loader

Python ETL process that extracts, transforms, and loads DAT data into RDF format with deduplication and enrichment logic.

3️⃣ Triple Store

Apache Jena Fuseki semantic database storing all DATs as linked data in named graphs, queryable via SPARQL.

4️⃣ API Layer

Two FastAPI services (v1 for generic, v2 for test cases) that query the triple store and build hierarchical data trees.

5️⃣ Backend

PHP proxy layer (tool2.php) that routes frontend requests to the appropriate API version based on parameters.

6️⃣ Frontend

JavaScript application (tool2.js) that loads 4 data types in parallel, indexes them, and renders an interactive UI for users.

🔄 Data Flow Paths

  1. Commercial Crop DATs: Excel → Loader → Triple Store → API v1 → PHP → JS → HTML
  2. Commercial Livestock DATs: Excel → Loader → Triple Store → API v1 → PHP → JS → HTML
  3. Test Case Crop DATs: Excel → Loader → Triple Store → API v2 → PHP → JS → HTML
  4. Test Case Livestock DATs: Excel → Loader → Triple Store → API v2 → PHP → JS → HTML
